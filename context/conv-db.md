# Database conventions

PostgreSQL with `vector`, `pg_trgm`, `unaccent` and `citext`. Drizzle for the schema and typed queries; raw `sql` for FTS, vector distance, recursive queries, leases and RLS.

## Schema rules

- Every tenant-scoped table carries `tenant_id uuid not null` and an index whose first column is `tenant_id`.
- Parent-child relations use **composite foreign keys** including `tenant_id`, so a row cannot reference another tenant's row even by a bug.
- Pages are unique on `(brain_id, slug)` where `deletion_state = 'active'`. Connections are canonical: `page_a_id < page_b_id`, unique on `(brain_id, page_a_id, page_b_id)`.
- `page_versions` is append-only. No `UPDATE` or `DELETE` grant for the application role.
- IDs are prefixed strings stored as `text`, not `uuid`, so the wire format never needs translation.
- Soft delete is a `deletion_state` column plus a partial index. Hard delete is a cascade and is only reachable through the `permanent=true` path.

## Migrations

- One migration per change, generated by `drizzle-kit`, reviewed by hand, and never edited after merge.
- A migration that drops or renames a column needs a backfill plan in the same file: add, backfill, switch reads, then drop in a later migration.
- Adding an index on a large table uses `CREATE INDEX CONCURRENTLY`, which cannot run inside a transaction; the migration notes that.
- Every migration is tested by running the full suite against a fresh database.

## Tenancy

Predicates are primary; RLS is defence in depth. Both are required.

```sql
ALTER TABLE pages ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON pages
  USING (tenant_id = current_setting('app.tenant_id', true)::uuid);
```

- A request sets `app.tenant_id` and `app.subject_id` with `SET LOCAL` **inside its transaction**. A pooled connection that sets it outside a transaction leaks scope to the next request.
- A missing setting must fail closed: no rows, never all rows. A test asserts this.
- Workers read the tenant from the job row and set the same variables. A worker never processes two tenants on one unscoped query.

## Search

- Full text: a generated `search_tsv` column, weighted `title` A, `summary` B, `body` C, with a GIN index.
- Vector: `embedding vector(1536)`. Exact search (`ORDER BY embedding <=> $1`) until the benchmark proves otherwise. HNSW is a measured decision, not a default, because filtered approximate search loses recall.
- One embedding row per `(page_id, model)`. Never mix models in one comparison; `model` and `dimensions` are stored on every row.
- Re-embedding is keyed by `content_hash`. An unchanged page costs nothing.

## Jobs

- One `jobs` table. Claim with `FOR UPDATE SKIP LOCKED` inside a short transaction, set `lease_until`, commit, then work.
- A crashed worker's lease expires; another worker claims it after `available_at`. Attempts increment on claim, not on failure.
- Backoff is exponential with jitter, capped. After `max_attempts` the job is `dead` and visible in the inspector.

## Performance

- Every list query has a matching index and a `LIMIT`. No unbounded scan reaches an endpoint.
- `EXPLAIN (ANALYZE, BUFFERS)` is pasted into the report for any new query on a table that can exceed 10k rows.
- Pagination is offset-based for compatibility, but the query always orders by an indexed, deterministic key.
